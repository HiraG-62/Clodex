# SHARED-BUTTON: 「資料」を「成果物」とは別のボタンにする

今は「成果物」のボタン 1 つで開くシートに、資料（上）と成果物（下）の 2 つの欄が並ぶ。資料は Agent が人に見せるために出したもので、見るきっかけも頻度も違うため、別のボタンにして、新しい資料が出たらボタンに点を付ける。仕様の正は `docs/DESIGN.md` §28「B — 成果物のプレビュー」と §「レイアウト」のヘッダ。

## 変更

対象のファイルは目安。同じ目的のために要るファイルは確認せずに触ってよい。

1. **ボタン**（`src/web/web-page.ts`、`src/web/client/viewport.ts`、`src/i18n/messages.ts`）
   - PC のヘッダのトレイで、成果物の前に資料のボタン（`open-shared`、アイコンは `paperclip`。アイコンの定義が無ければ足す）を置く。項目が無い会話でも出す
   - スマホの ⋯ のメニューにも、成果物の前に資料の行を足す
   - 文言: ja「資料」/ en "Shared"（`web.top.shared` など）
2. **シート**（`src/web/client/artifacts-lightbox.ts`）
   - 資料のボタンは `group === "presented"` だけ、成果物のボタンは `group === "work"` だけのシートを開く。シートの見出しはそれぞれ「資料」「成果物」。欄の見出し（`artifact-group`）は不要になるので消す
   - 空のときは今の「ファイルはまだありません」
   - ビューア（差分・全体の切り替え）は今のまま。ビューアから戻る先は開いたシート（資料なら資料）
   - `sheetKind` は `"shared"` を足すなど、開いているシートを feed の更新で描き直す今の仕組みが両方で動くようにする
3. **新しい資料の点**
   - 会話ごとに、資料のシートを最後に開いた時刻を localStorage に持つ（key は会話の id を含める）
   - 資料のうち `at` がその時刻より新しいものがあれば、資料のボタン（PC のボタンとスマホの ⋯ のボタン・メニューの行）に小さな点を付ける。一度も開いていない会話は資料が 1 つでもあれば点を付ける
   - シートを開いたら（開いている間に資料が増えたときも）時刻を更新して点を消す
   - 判定（資料の一覧と最後に開いた時刻 → 点の有無）は純粋な関数にする
4. 文言は短く。「この〜」の言い回しは使わない。使わなくなった文言（`web.artifacts.presented` など）は消す

## テスト方針

- 点の判定の純粋な関数: 一度も開いていない（資料あり / なし）、開いた後に新しい資料、開いた後に新しいのは成果物だけ
- `web-page.test.ts`: `open-shared` のボタンがある
- 画面は CLAUDE.md / AGENTS.md の「画面の確認（Web UI）」の手順で、資料と成果物の両方がある会話を作り、PC とスマホの幅で、2 つのボタン・それぞれのシート・点（開く前と開いた後）を確かめ、スクリーンショットの path を RESULT に書く
- `pnpm test`・`pnpm typecheck`・`pnpm lint`。コミットはしない。終わったら `send_message` の RESULT で報告する
