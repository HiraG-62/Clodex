# WORKLOG-DROPDOWN: 作業ログをボタンの下に開き、見出しを固定する

作業ログのボタンは PC ではヘッダの右上にあるのに、パネルは右の横から出てくる。また、パネルの見出し（「作業ログ」と閉じるボタン）が中身と一緒にスクロールで流れる。仕様の正は `docs/DESIGN.md` §「作業ログ」。

## 変更

対象のファイルは目安（作業ログのパネルの描画・開閉のコードと `src/web/client/style.css`）。同じ目的に要るファイルは確認せずに触ってよい。

1. **PC**: パネルをヘッダの作業ログのボタンの真下から、右上に寄せたパネルとして開く。ログの上に重ねる（幅はおよそ 440px、画面が狭ければ収まる幅。高さはログの下端まで）。もう一度ボタンを押す・Esc・パネルの外のクリックで閉じる。開くときは上から下へ短く広げる（`prefers-reduced-motion` では動かさない）。開いている間はボタンを押された状態（`aria-pressed` / `aria-expanded`）にする
2. **スマホ**: 今の下から開くシートのまま
3. **見出しの固定**（PC・スマホとも）: 見出しを固定し、中身だけをスクロールする。今の「一番下を見ていたら新しい発言に合わせて下へスクロール」は中身のスクロールで続ける
4. 見出しを押してログのターンへ移動する動きなど、今の機能は変えない

## テスト方針

- 開閉の判定を純粋な関数にするなら、それをテストする
- 画面は CLAUDE.md / AGENTS.md の「画面の確認（Web UI）」の手順で、発言が多い作業ログ（feed を流し込んでよい）を開き、PC はボタンの下に開いた状態とスクロールした後でも見出しが残る状態、スマホは見出しが残る状態のスクリーンショットを撮って RESULT に path を書く
- `pnpm test`・`pnpm typecheck`・`pnpm lint`。コミットはしない。終わったら `send_message` の RESULT で報告する
