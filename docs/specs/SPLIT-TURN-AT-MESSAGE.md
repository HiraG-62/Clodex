# SPLIT-TURN-AT-MESSAGE: message を送ったところでターンの枠を区切る

作業中のターンの枠はログの一番下に置いている（`withWorkingTurnsLast`）。そのターンで QUESTION を送り、相手が先に回答（RESULT）すると、回答のターンは終わって固定されるのに、質問はまだ作業中の枠の中にあるので、回答より下に表示される（時系列が逆）。message を送ったところで枠を区切り、そこまでを固定する。仕様の正は `docs/DESIGN.md` §17 ログの「作業中のターンで message を送ったら、そこでターンの枠を区切る」。

## 変更（`src/web/client/timeline.ts`、描画は `src/web/client/log-item.ts`、作業ログは `src/web/client/log-view.ts`。`client-main.ts` は必要なときだけ）

1. **区切る**: `message` event（`ACK` 以外）で送信元の作業中のターンがあれば
   - そのターンの今の枠に message を足したうえで、枠を「固定した区切り」にする（例: `status` は今のまま持ちつつ `segment: "closed"` のような印を付け、作業中として扱わない＝一番下へ寄せない。ログの末尾へ移す）
   - 同じターンの続きの枠を新しく作り、作業中として一番下に置く（`plan` は無し。続きの最初の発言は作業の `say` として並べる。turn の識別のため、元の枠の ID を持たせてもよい）
   - 続きの枠がまだ空（発言・tool・message が無い）で、直前に固定した同じターンの枠がログの最後の項目なら、新しい message はその固定した枠に足す（続けて送った message で枠を細かく分けない）
2. **終わり**（`turn` event）
   - 続きの枠に作業も message も無ければ、続きの枠は消し、最終応答を最後に固定した同じターンの枠の `steps` の最後に `say` として足す（今の「message がある枠は最終応答を作業に入れる」描画と同じ見え方になる）
   - 続きの枠に中身があれば、今どおりその枠を末尾に固定し、最終応答を出す
   - 区切っていないターンは今どおり
3. **描画**: 固定した区切りの枠は状態（作業中・完了）を出さない。続きの枠の見出しは Agent 名・状態・経過時間（方針の行は無し）
4. **自動の RESULT** は、送信元の最後の枠（区切りを含む）に足す（今の「直前に終わったターン」と同じ考え方）
5. **作業ログ**（`workingFeed`）: 区切った枠と続きの枠を同じターンとして数える（直近 2 ターンの数え方を変えない）
6. 保存する feed は今のまま。`rebuildTimeline`（読み込み直し）でも同じ並びになること

## テスト方針（`timeline.test.ts`）

- 作業中に QUESTION を送る → 相手の RESULT のターンが終わる → 表示の並びが「質問を含む枠 → 回答の枠 → 続きの作業中の枠」
- 依頼して終えるターン（send_message → 最終応答だけ）は 1 つの枠で、最終応答は畳んだ作業の最後
- 区切った後に作業を続けて終える → 続きの枠に最終応答が出る
- 続けて 2 つ送る（間に作業なし・ほかの項目なし）→ 同じ枠に 2 つ
- 自動の RESULT は最後の枠に入る
- `rebuildTimeline` でも同じ
- 画面は CLAUDE.md / AGENTS.md の「画面の確認（Web UI）」の手順で、feed を差し込んで上の 1 つ目の並びを確かめ、スクリーンショットの path を RESULT に書く
- `pnpm test`・`pnpm typecheck`・`pnpm lint`。コミットはしない。終わったら `send_message` の RESULT で報告する
