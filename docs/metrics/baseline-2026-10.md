ターンと task は宛先の待ち行列から推定。人の入力は未割当。キャッシュ内訳・出力・rework は過去の記録にないため集計対象外。時間の単位は ms。欠測 token は 0 として集計。

参考値との差: message 1,214 件・ターン 1,961 件に対し、対象ログでは 1,236 件・1,985 件。QUESTION あり 44%・2 件以上 18% に対し 44.14%・18.21%、roguelike の QUESTION/DELEGATE 1.26 に対し 1.24。

QUESTION は replyTo が DELEGATE を指す場合はそれを優先し、その他は同じ task の直近の DELEGATE に対応させる。ターンの割当は宛先の mailbox 順で推定し、人の入力を優先する。配送記録がないため割り込み・再開によるずれを含む。

Claude context は短いターンも含む全完了ターンの最終観測値を採用し、一度も観測していないターンは中央値の分母から除く。参考の中央値 369k・150k 超 92% に対し、今回は全 project で 310,671.5（約310k）・75.95%（約76%）、roguelike では 379,813（約380k）・83.64%（約84%）。元集計の条件は記録されていない。短いターンの採否・project の範囲の違いが差の原因として考えられる。

古い記録に inputTotal がないため task の入力 token は観測できた分の合計であり下限値。RESULT 受信入力の中央値は累計を観測したターンだけを対象にする。キャッシュ込みの基準値であり、導入後の通常入力だけの値とは直接比較しない。
